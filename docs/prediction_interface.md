# Historical rainfall prediction interface

A single-page Streamlit dashboard loads the existing GBT-05 Spark PipelineModel.
Users select a monitoring station, prediction date/time and rainfall threshold.
The app predicts strict exceedance of next-30-minute rainfall, plots the preceding
hour, and optionally retrieves the historical outcome in a separate section.
There is no model training, probability adjustment or simulated output.

## Requirements

- Python 3.11 recommended (local checks used 3.11); Java 11 or 17 available on PATH.
  If Java 21 is selected, follow the [README's Java setup](../README.md#1-set-up-the-interface-environment)
  to select Java 17 before launching this Spark 3.5.6 environment.
- `requirements-interface.txt`: Streamlit 1.56.0 and PySpark 3.5.6, matching GBT.
  Use a separate environment from the Spark 3.3.1 training and plotting setups.
- The committed GBT-05 model, already included in this repository.
- The committed `data/demo/rainfall_2024` is sufficient for the quick start:
  4,608 real cleaned readings from eight stations on 1–2 January 2024:
  S24, S33, S50, S104, S109, S115, S116 and S117.
- For full coverage, cleaned annual Parquet under a root containing
  `rainfall_2017` through `rainfall_2024`, generated by the existing cleaning code.

The full cleaned dataset is not in Git. The prepared modelling dataset alone is
not the input here: the app needs individual cleaned observations for history
lookup and the optional outcome check. With no data connected, the page gives
setup instructions rather than displaying fabricated estimates.

## Quick start: included demonstration data

From the repository root:

```bash
python3.11 -m venv .venv-interface
.venv-interface/bin/python -m pip install -r requirements-interface.txt
java -version

unset RAINFALL_DATA_ROOT  # Use the bundled demo, even after a full-data session.
SPARK_LOCAL_IP=127.0.0.1 .venv-interface/bin/python -m streamlit run streamlit_app.py \
  --server.address 127.0.0.1 --browser.gatherUsageStats false
```

Open http://localhost:8501. Spark and the model are cached; the station catalog
is cached for ten minutes. The app identifies demonstration data and shows its
stations, dates and prediction/verification bounds. See [dataset provenance](../data/demo/README.md).
This subset is not used to calculate the report's metrics and is not representative
for evaluation. Input defaults use the first station and threshold: S24,
1 January 2024 at 00:00 SGT, and 0 mm. That initial midnight lacks the preceding
hour in the demo; choose 01:00 or later that day, or 2 January at 00:00.
Only supplied observations can be queried.

If the terminal reports `Port 8501 is not available`, the new server has not
started. Use `--server.port 8504` and open http://localhost:8504, or stop the old
server in its own terminal. The optional Streamlit email prompt can be skipped
with Enter. See the [README troubleshooting instructions](../README.md#2-run-the-included-demonstration).

Optional wet-weather example: S24 at 14:10 SGT on 1 January, threshold 5 mm,
predicts 54.9%; the observed subsequent total is 19.60 mm. The previous S50
example at 13:50 predicts 67.9% but observes only 0.40 mm, so the >5 mm event
does not occur. Neither example should be used to infer overall model quality.

The default is always the bundled demo. To use full data, set the variable below
explicitly, even when the data is already in `data/processed/`. Restart the app
when changing data roots.

To use another cleaned-data location:

```bash
export RAINFALL_DATA_ROOT="/absolute/path/to/processed"
SPARK_LOCAL_IP=127.0.0.1 .venv-interface/bin/python -m streamlit run streamlit_app.py \
  --server.address 127.0.0.1 --browser.gatherUsageStats false
```

To download your existing cleaned data from Vanda (optional; potentially large):

rsync -avh --progress \

## Connect the full public dataset

This workflow runs on macOS or Linux (Windows through WSL2), without a Vanda
account. Install the interface requirements and Java first, as above. Full-data
processing needs substantially more memory, disk and time than the demo. The
recorded full cleaning run used Spark 3.3.1 on Vanda; the interface and cleaner
functions were tested locally with Spark 3.5.6, but the entire eight-year cleaning
run has not been repeated on a laptop in this revision.

1. Open the NEA [Historical Rainfall across Singapore collection](https://data.gov.sg/collections/2279/view).
   Download the full CSV for each year **2017–2024**; exclude 2016. Extract archives
   if necessary and rename the files to the exact paths below. Use full CSV
   downloads, not a paginated API sample. Source timestamps are Singapore time.

   ```text
   data/raw/HistoricalRainfallacrossSingapore2017.csv
   data/raw/HistoricalRainfallacrossSingapore2018.csv
   data/raw/HistoricalRainfallacrossSingapore2019.csv
   data/raw/HistoricalRainfallacrossSingapore2020.csv
   data/raw/HistoricalRainfallacrossSingapore2021.csv
   data/raw/HistoricalRainfallacrossSingapore2022.csv
   data/raw/HistoricalRainfallacrossSingapore2023.csv
   data/raw/HistoricalRainfallacrossSingapore2024.csv
   ```

2. From the repository root, check inputs and create an isolated workspace. This
   uses the existing scripts without overwriting the committed cleaning summaries
   or other experimental results.

   ```bash
   for year in {2017..2024}; do
     ls -lh "data/raw/HistoricalRainfallacrossSingapore${year}.csv"
   done

   mkdir -p .local-cleaning/src .local-cleaning/data
   cp src/data_cleaning.py src/cleaning_validation.py .local-cleaning/src/
   test -e .local-cleaning/data/raw || ln -s "$PWD/data/raw" .local-cleaning/data/raw
   export PYSPARK_PYTHON="$PWD/.venv-interface/bin/python"
   export SPARK_LOCAL_IP=127.0.0.1

   .venv-interface/bin/spark-submit --master 'local[4]' --driver-memory 8g \
     .local-cleaning/src/data_cleaning.py
   .venv-interface/bin/spark-submit --master 'local[4]' --driver-memory 8g \
     .local-cleaning/src/cleaning_validation.py
   ```

   The example requests four threads and an 8 GB Java driver heap; allow additional
   memory for the OS/Python and use a machine with sufficient RAM. Adjust resources
   for your machine. Stop if cleaning or validation fails; inspect the command
   output and `.local-cleaning/outputs/validation/`. These commands clean and
   validate observations; they do not train or evaluate models.

3. Connect the resulting full cleaned dataset and launch the same interface:

   ```bash
   export RAINFALL_DATA_ROOT="$PWD/.local-cleaning/data/processed"
   SPARK_LOCAL_IP=127.0.0.1 .venv-interface/bin/python -m streamlit run streamlit_app.py \
     --server.address 127.0.0.1 --browser.gatherUsageStats false
   ```

   All available stations and dates are derived from that data. The first catalog
   scan can take time. Missing observation windows still produce helpful errors.
   If you already have full cleaned data, skip steps 1–2 and point the variable to
   its root (for example, `$PWD/data/processed`). To return to the demo, stop the
   app, run `unset RAINFALL_DATA_ROOT`, and launch it again.

The report's recorded training/validation/test cohorts, sampling choices and
metrics remain unchanged. Connecting observations for historical replay does not
reproduce a training experiment or generate a new performance estimate.

## Run on Vanda without downloading data

Use your repository checkout containing this interface branch. On Vanda, create
a separate environment using Python/Java modules (not Spark/3.3.1):

```bash
cd /scratch/e0969984/singapore-rainfall-analysis-and-prediction
# Upload the interface files with rsync, or use a Git clone of the interface branch.
# A folder copied with rsync is not a Git checkout.
module load Python/3.10.4-GCCcore-11.3.0 Java/11.0.18
python3 -m venv .venv-interface
.venv-interface/bin/python -m pip install -r requirements-interface.txt
JOB_ID=$(qsub jobs/prediction_interface_vanda.pbs)
echo "$JOB_ID"
qstat -xf "$JOB_ID" | grep -E 'job_state|Exit_status'
```

The PBS file requests 2 cores/12 GB for two hours and uses your own cleaned data.
It prints the compute-node hostname in `rainfall_interface.oJOB_NUMBER`. Retrieve
that hostname from the log (or `qstat -f JOB_ID`'s `exec_host` while the job runs).
On your Mac, replace COMPUTE_NODE with it, keep this tunnel open, and visit
http://localhost:8501:

```bash
ssh -N -L 8501:COMPUTE_NODE:8501 e0969984@vanda.nus.edu.sg
```

The app binds the compute-node interface for the tunnel; keep access inside the
cluster and the SSH tunnel. Stop the session with `qdel JOB_ID` when finished.
The user has confirmed PBS job startup with these modules and Streamlit listening
on a compute node. Full remote inference has not been independently verified in
this revision. Cluster port-forwarding rules may require adjustment on Vanda.
Do not launch the Spark web app on the login node.

## Inputs, features and output

- Station dropdown: IDs actually present in the connected Parquet, labelled using
  the existing station-name mapping. The dropdown supports typing to search.
- Station map: click an ID-labelled point to select it; the dropdown and orange
  map highlight stay synchronized. Changing station clears the preceding result
  and refreshes the available date range. Only connected stations are shown.
  Positions use the latest valid latitude/longitude pair recorded for each
  station, without averaging different locations. Historical coordinates may
  differ. Missing/invalid coordinates leave the station available in the dropdown.
  If all coordinates are absent, the app explains why the map is unavailable.
- Timestamp: Singapore time, 2017–2024, on the exact five-minute grid. Displayed
  record ranges do not guarantee uninterrupted coverage; gaps produce clear errors.
- Threshold dropdown: the four evaluated values 0, 1, 5, 10 mm, defaulting to the first option, 0 mm.
  Other values cannot be selected and are also rejected by the inference module.
- The selected time requires an observation at t and all twelve readings t−60,
  t−55, …, t−5. The observation at t is excluded from predictor values, exactly as
  in training. No rounding or missing-to-zero substitution is applied.
- Predictors: station, hour, month, t−5 rainfall, sums t−30…t−5 and t−60…t−5,
  and rainfall threshold. The saved pipeline performs its own fitted encoding.
- Target: six readings at t+5, t+10, …, t+30. Equality to the threshold is negative.
  The UI displays the issued/end times and exact target-reading interval.
- The model probability is vector element 1, displayed as a percentage rounded
  to one decimal place. Historical verification is a separate user-triggered read
  requiring all six future slots. Missing future data does not prevent inference.
- The history chart has an explicit zero lower bound. All-zero windows use a
  0–1 mm scale; wet windows use an upper bound just above their largest reading.

This is retrospective replay, not live forecasting. Earlier years were used in
training/validation; users should not interpret those queries as held-out results.
No probability recalibration is fitted, and rare heavy-rain probabilities may be
unreliable. The adapter uses observation timestamps, not a live data arrival feed.

## Architecture and checks

`streamlit_app.py` handles inputs, charts and result display.
`src/rainfall_inference.py` loads cleaned Parquet, reuses the existing timestamp
normalizer, constructs the exact historical features, and calls the saved model.
A lock serializes Spark calls across UI sessions. Only the selected bounded window
is collected; full historical observations remain in Spark. Model and Spark
resources use Streamlit's resource cache; the small station catalog uses its data
cache. Data is assumed read-only; restart the app if the underlying files change.

The map uses Altair's built-in selection events, with no new dependencies, map
API keys or external tile requests. `data/geography/singapore_adm0.geojson` is the
same boundary bundled for Task 1. Its [source metadata](../data/geography/singapore_boundary_source.json)
records the geoBoundaries/URA-derived source and ODbL 1.0 licence. Polygon winding
is adapted in memory for Vega; the original boundary file is unchanged. Restart
the Streamlit process after updating inference code to refresh cached resources.

Optional configuration: `RAINFALL_MODEL=RF` or `LR` uses the other committed
pipelines. `RAINFALL_SPARK_MASTER` defaults to `local[2]` and
`RAINFALL_DRIVER_MEMORY` to `4g`. Restart when changing resource configuration.

Run focused tests using the interface environment:

```bash
.venv-interface/bin/python -m pip install -r requirements-test.txt
SPARK_LOCAL_IP=127.0.0.1 .venv-interface/bin/python -m pytest -q \
  tests/test_rainfall_interface.py tests/test_rainfall_app.py
```

All 13 focused tests passed using Spark 3.5.6 and Python 3.11, including the
bundled real-data default launch, station/date changes and probability parity.
Checks also cover coordinate-pair selection, numeric station sorting and missing
coordinates. Map clicks and dropdown/highlight synchronization were verified in
the local browser using real station locations and saved-model inference.
Tests compare all four GBT probabilities to the original preparation/model path,
check missing/off-grid/unsupported inputs, future-data exclusion and UI output
using the actual committed model (no mocked probabilities).

A separate isolated-copy check also launched the app with only its source, the
saved GBT, station-name map and bundled demo, with no raw files, full processed
data or Vanda connection. Both prediction and subsequent-observation lookup
worked. This verifies the packaged-data launch, not a fresh dependency install
on every operating system; WSL and full laptop cleaning remain unverified.

Additional manual verification used 19 real source observations for station S33,
1 January 2024 at 01:00 SGT, passed through the existing cleaner into temporary
Parquet. Interface probabilities matched the original pipeline within 1e−12 at
all four thresholds. For >5 mm, the underlying probability 0.03434658346826358
was correctly displayed as 3.4%; the separately retrieved actual total was 0 mm.
This is one historical query, not a new performance evaluation. The larger
committed two-day demo now provides a reproducible quick start using
the same saved model, with no hardcoded predictions.
