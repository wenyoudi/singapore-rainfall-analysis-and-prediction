# Historical rainfall prediction interface

A single-page Streamlit dashboard loads the existing GBT-05 Spark PipelineModel.
Users select a monitoring station, prediction date/time and rainfall threshold.
The app predicts strict exceedance of next-30-minute rainfall, plots the preceding
hour, and optionally retrieves the historical outcome in a separate section.
There is no model training, probability adjustment or simulated output.

## Requirements

- Python 3.11 recommended (local checks used 3.11); Java 11 or 17 available on PATH.
- `requirements-interface.txt`: Streamlit 1.56.0 and PySpark 3.5.6, matching GBT.
  Use a separate environment from the Spark 3.3.1 training and plotting setups.
- The committed GBT-05 model, already included in this repository.
- Cleaned annual Parquet under a data root containing `rainfall_2017` through
  `rainfall_2024`, generated by the existing cleaning pipeline. A subset of annual
  directories also works; only stations/dates present there are offered.

The large cleaned dataset is not in Git. The prepared modelling dataset alone is
not the input here: the app needs individual cleaned observations for history
lookup and the optional outcome check. With no data connected, the page gives
setup instructions rather than displaying fabricated estimates.

## Launch on your Mac

From the repository root:

```bash
python3.11 -m venv .venv-interface
.venv-interface/bin/python -m pip install -r requirements-interface.txt
java -version

# If data/processed already contains the cleaned annual Parquet:
SPARK_LOCAL_IP=127.0.0.1 .venv-interface/bin/python -m streamlit run streamlit_app.py \
  --server.address 127.0.0.1 --browser.gatherUsageStats false
```

Open http://localhost:8501. Spark and the model are cached; the station catalog
is cached for ten minutes. The first catalog scan can take time on the full data.

To use another cleaned-data location:

```bash
export RAINFALL_DATA_ROOT="/absolute/path/to/processed"
SPARK_LOCAL_IP=127.0.0.1 .venv-interface/bin/python -m streamlit run streamlit_app.py \
  --server.address 127.0.0.1 --browser.gatherUsageStats false
```

rsync -avh --progress \
  e0969984@vanda.nus.edu.sg:/scratch/e0969984/singapore-rainfall-analysis-and-prediction/data/processed/ \

## Run on Vanda without downloading data

Use your repository checkout containing this interface branch. On Vanda, create
a separate environment using Python/Java modules (not Spark/3.3.1):

```bash
cd /scratch/e0969984/singapore-rainfall-analysis-and-prediction
git fetch origin
git switch task2/prediction-interface
module load Python/3.10.4-GCCcore-11.3.0 Java/11.0.18
python3 -m venv .venv-interface
.venv-interface/bin/python -m pip install -r requirements-interface.txt
JOB_ID=$(qsub jobs/prediction_interface_vanda.pbs)
echo "$JOB_ID"
qstat -xf "$JOB_ID" | grep -E 'job_state|Exit_status'
```

The PBS file requests 2 cores/12 GB for two hours and uses your own cleaned data.
It prints the compute-node hostname in `rainfall_interface.oJOB_NUMBER`. Retrieve
that hostname from the log (or `qstat -f JOB_ID`'s `exec_host` while the job runs).
On your Mac, replace COMPUTE_NODE with it, keep this tunnel open, and visit
http://localhost:8501:

```bash
ssh -N -L 8501:COMPUTE_NODE:8501 e0969984@vanda.nus.edu.sg
```

The app binds the compute-node interface for the tunnel; keep access inside the
cluster and the SSH tunnel. Stop the session with `qdel JOB_ID` when finished.
The module names match the recorded Vanda stack; the interface job itself has not
been submitted or verified remotely. Module availability, package access and
cluster port-forwarding rules may require adjustment on Vanda. Do not launch the
Spark web app on the login node.

## Inputs, features and output

- Station dropdown: IDs actually present in the connected Parquet, labelled using
  the existing station-name mapping. The dropdown supports typing to search.
- Timestamp: Singapore time, 2017–2024, on the exact five-minute grid. Displayed
  record ranges do not guarantee uninterrupted coverage; gaps produce clear errors.
- Threshold dropdown: the four evaluated values 0, 1, 5, 10 mm, defaulting to 5 mm.
  Other values cannot be selected and are also rejected by the inference module.
- The selected time requires an observation at t and all twelve readings t−60,
  t−55, …, t−5. The observation at t is excluded from predictor values, exactly as
  in training. No rounding or missing-to-zero substitution is applied.
- Predictors: station, hour, month, t−5 rainfall, sums t−30…t−5 and t−60…t−5,
  and rainfall threshold. The saved pipeline performs its own fitted encoding.
- Target: six readings at t+5, t+10, …, t+30. Equality to the threshold is negative.
  The UI displays the issued/end times and exact target-reading interval.
- The model probability is vector element 1, displayed as a percentage rounded
  to one decimal place. Historical verification is a separate user-triggered read
  requiring all six future slots. Missing future data does not prevent inference.

This is retrospective replay, not live forecasting. Earlier years were used in
training/validation; users should not interpret those queries as held-out results.
No probability recalibration is fitted, and rare heavy-rain probabilities may be
unreliable. The adapter uses observation timestamps, not a live data arrival feed.

## Architecture and checks

`streamlit_app.py` handles inputs, charts and result display.
`src/rainfall_inference.py` loads cleaned Parquet, reuses the existing timestamp
normalizer, constructs the exact historical features, and calls the saved model.
A lock serializes Spark calls across UI sessions. Only the selected bounded window
is collected; full historical observations remain in Spark. Model and Spark
resources use Streamlit's resource cache; the small station catalog uses its data
cache. Data is assumed read-only; restart the app if the underlying files change.

Optional configuration: `RAINFALL_MODEL=RF` or `LR` uses the other committed
pipelines. `RAINFALL_SPARK_MASTER` defaults to `local[2]` and
`RAINFALL_DRIVER_MEMORY` to `4g`. Restart when changing resource configuration.

Run focused tests using the interface environment:

```bash
.venv-interface/bin/python -m pip install -r requirements-test.txt
SPARK_LOCAL_IP=127.0.0.1 .venv-interface/bin/python -m pytest -q \
  tests/test_rainfall_interface.py tests/test_rainfall_app.py
```

All 11 focused tests passed locally using Spark 3.5.6 and Python 3.11.
Tests compare all four GBT probabilities to the original preparation/model path,
check missing/off-grid/unsupported inputs, future-data exclusion and UI output
using the actual committed model (no mocked probabilities).

Additional manual verification used 19 real source observations for station S33,
1 January 2024 at 01:00 SGT, passed through the existing cleaner into temporary
Parquet. Interface probabilities matched the original pipeline within 1e−12 at
all four thresholds. For >5 mm, the underlying probability 0.03434658346826358
was correctly displayed as 3.4%; the separately retrieved actual total was 0 mm.
This is one historical query, not a new performance evaluation. No test slice or
hardcoded prediction is shipped with the app; connect your real cleaned dataset.
